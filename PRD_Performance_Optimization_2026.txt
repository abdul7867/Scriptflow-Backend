This PRD outlines a comprehensive performance optimization initiative for ScriptFlow's AI-powered script generation platform. The goal is to achieve **15-25 second script delivery** while reducing infrastructure costs by **73%** through Redis optimization and implementing faster, more reliable Instagram reel download methods.

### Key Objectives
1. **Reduce Redis command usage by 73%** (5,755 → 1,555 commands per 10 requests)
2. **Achieve 15-25 second script generation** (down from 30-50 seconds)
3. **Implement 99.9% reliable reel downloads** (2-5 second average)
4. **Maintain or improve user experience** (no speed degradation)

## 1. Background & Problem Statement

### Current State Analysis

**Redis Usage Crisis:**
- **Current:** 5,755 commands per 10 external requests (575:1 ratio)
- **Problem:** BullMQ polling consumes 90% of Redis commands even when idle
- **Impact:** Only 28 requests/day possible with 500K monthly limit
- **Root Cause:** Constant polling + excessive state checks + redundant operations

**Script Generation Performance:**
- **Current:** 30-50 seconds for first-time reels
- **Breakdown:**
  - Video download: 8-15s (40% of time)
  - Frame extraction: 3-6s (15%)
  - Audio extraction: 2-4s (10%)
  - Gemini analysis: 5-8s (20%)
  - Script generation: 3-5s (10%)
  - Other: 4-6s (5%)
- **User Impact:** High abandonment rate, perceived as "slow"

**Download Reliability:**
- **Current:** 3-tier fallback (yt-dlp + Cobalt + yt-dlp no-cookies)
- **Success Rate:** ~85% (15% failure rate)
- **Speed:** 8-15 seconds average
- **Issue:** Heavy dependency on yt-dlp which is slow and occasionally blocked

### Business Impact
- **Cost:** Exceeding Upstash free tier, potential $50-100/month if scaled
- **User Satisfaction:** Competitors deliver scripts in 10-15 seconds
- **Scalability:** Cannot handle >28 requests/day without cost increase
- **Reliability:** 15% download failure rate causes user frustration

### 2.2 Optimization Strategy

#### High Impact Optimizations (60-70% savings)

**2.2.1 BullMQ Configuration**
```typescript
// Current settings
{
  stalledInterval: 30000,  // Default
  lockDuration: 30000      // Default
}

// Proposed settings
{
  stalledInterval: 60000,  // 2x slower polling
  lockDuration: 60000,     // Longer locks
  settings: {
    lockRenewTime: 30000   // Optimize renewal
  }
}
```

**Impact:** -3,000 commands (60% reduction in BullMQ overhead)  
**Risk:** None - jobs picked up instantly via Pub/Sub  
**Implementation Time:** 30 minutes

**2.2.2 Circuit Breaker In-Memory Cache**
```typescript
// Add 10-second TTL cache
private stateCache: {
  state: CircuitState;
  timestamp: number;
} | null = null;

async getState(): Promise<CircuitState> {
  const now = Date.now();
  if (this.stateCache && now - this.stateCache.timestamp < 10000) {
    return this.stateCache.state; // Return from cache
  }
  
  // Fetch from Redis only if cache expired
  const state = await redis.get(`${this.redisKeyPrefix}:state`);
  this.stateCache = { state, timestamp: now };
  return state;
}
```

**Impact:** -400 commands (80% reduction in circuit breaker reads)  
**Risk:** Low - 10s delay acceptable for state propagation  
**Implementation Time:** 2 hours

**2.2.3 Session Manager Conditional TTL Refresh**
```typescript
// Only refresh TTL if >50% expired
async updateSession(subscriberId: string, updates: Partial<SessionContext>) {
  const key = getSessionKey(subscriberId);
  const ttl = await redis.ttl(key);
  
  const updated = { ...existingSession, ...updates, lastActivityAt: new Date() };
  
  // Only set new expiry if >50% expired
  if (ttl < SESSION_TTL_SECONDS / 2) {
    await redis.setex(key, SESSION_TTL_SECONDS, JSON.stringify(updated));
  } else {
    await redis.set(key, JSON.stringify(updated)); // No TTL update
  }
}
```

**Impact:** -300 commands (50% reduction in session writes)  
**Risk:** None - sessions still valid  
**Implementation Time:** 1 hour

#### Medium Impact Optimizations (10-20% savings)

**2.2.4 FSM TTL Removal**

// Remove unnecessary TTL check
const [data, ttl] = await Promise.all([

## 4. Instagram Reel Download Enhancement

### 4.1 Current State Analysis

**Existing Cascade:**
```typescript
1. yt-dlp with cookies    → 8-15s, 75% success
2. Cobalt API            → 6-10s, 70% success  
3. yt-dlp without cookies → 8-15s, 65% success
```

**Issues:**
- ❌ Slow: 8-15 seconds average
- ❌ Unreliable: 15-30% failure rate
- ❌ Heavy: yt-dlp binary is 90MB+
- ❌ Blocked: Instagram rate-limits yt-dlp

### 4.2 Proposed Solutions

#### 4.2.1 Tier 1: Direct CDN Extraction (PRIMARY)

**Method:** Scrape Instagram's embedded JSON from HTML

```typescript
async function downloadViaDirectCDN(url: string, id: string): Promise<string> {
  // 1. Fetch Instagram page
  const response = await axios.get(url, {
    headers: {
      'User-Agent': 'Mozilla/5.0 (iPhone; CPU iPhone OS 15_0 like Mac OS X) AppleWebKit/605.1.15...',
      'Cookie': loadCookiesIfAvailable(),
    },
    timeout: 10000
  });
  
  // 2. Extract video URL from embedded JSON
  const jsonMatch = response.data.match(/window\._sharedData = ({.+?});/);
  if (!jsonMatch) {
    // Fallback: Try alternate JSON locations
    const jsonMatch2 = response.data.match(/<script type="application\/ld\+json">(.+?)<\/script>/);
  }
  
  const data = JSON.parse(jsonMatch[1]);
  const videoUrl = data.entry_data.PostPage[0].graphql.shortcode_media.video_url;
  
  // 3. Download video directly from CDN
  const videoResponse = await axios({
    method: 'GET',
    url: videoUrl,
    responseType: 'stream',
    timeout: 60000,
  });
  
  const outputPath = path.join(tempDir, `${safeId}.mp4`);
  await pipeline(videoResponse.data, fs.createWriteStream(outputPath));
  
  return outputPath;
}
```

**Advantages:**
- ⚡ **Ultra-fast:** 2-4 seconds (70% faster)
- 💰 **Free:** No external costs
- 🎯 **Reliable:** 95% success rate (direct from source)
- 🪶 **Lightweight:** No binary dependencies

**Disadvantages:**
- ⚠️ JSON structure may change (monitor required)
- ⚠️ Requires User-Agent rotation
- ⚠️ Rate limiting possible (use proxies if needed)

**Fallback Strategy:** If JSON structure changes, auto-detect and log for manual update

### 4.3 Proposed Cascade Architecture

```typescript
export async function downloadReel(url: string, id: string): Promise<string> {
  const methods = [
    // Tier 1: FASTEST & FREE (2-4s, 95% success)
    {
      name: 'direct-cdn',
      fn: () => downloadViaDirectCDN(url, id),
      priority: 1
    },
    
    // Tier 2: VERY RELIABLE (3-5s, 99% success) [OPTIONAL]
    ...(process.env.INSTAGRAPI_URL ? [{
      name: 'instagrapi',
      fn: () => downloadViaInstagrapi(url, id),
      priority: 2
    }] : []),
    
    // Tier 3: PROFESSIONAL FALLBACK (2-4s, 99% success) [FREE TIER]
    ...(process.env.RAPIDAPI_KEY ? [{
      name: 'rapidapi',
      fn: () => downloadViaRapidAPI(url, id),
      priority: 3
    }] : []),
    
    // Tier 4: OPTIMIZED LEGACY (5-10s, 85% success)
    {
      name: 'yt-dlp-optimized',
      fn: () => downloadViaYtDlpOptimized(url, id),
      priority: 4
    },
  ];
  
  // Circuit breaker wrapper
  return withCircuitBreaker('instagram-download', async () => {
    for (const method of methods) {
      try {
        logger.info(`[${id}] Attempting: ${method.name}`);
        const result = await method.fn();
        logger.info(`[${id}] ✅ Success via ${method.name}`);
        
        // Track metrics
        metrics.recordDownloadMethod(method.name, 'success');
        
        return result;
      } catch (error: any) {
        logger.warn(`[${id}] ❌ ${method.name} failed: ${error.message}`);
        metrics.recordDownloadMethod(method.name, 'failure');
        
        // Check if terminal error (don't retry)
        if (isTerminalError(error)) {
          throw error;
        }
        
        continue; // Try next method
      }
    }
    
    throw new Error('All download methods exhausted');
  });
}
```

## 10. Appendix

### A. Detailed Technical Specs

#### Redis Command Optimization Formula
```
Savings = (BullMQ_polling_reduction × 0.52) +
          (Circuit_breaker_cache × 0.07) +
          (Session_TTL_optimization × 0.10) +
          (FSM_simplification × 0.10) +
          (QueueEvents_removal × 0.12)

Expected = (3000 × 0.52) + (400 × 0.07) + ... = 4,200 commands saved
New Total = 5,755 - 4,200 = 1,555 commands per 10 requests
Reduction = 73%
```

#### Script Generation Time Calculation
```
Current Cold Path:
  Download(10s) + Frames(4s) + Audio(3s) + Analysis(6s) + Script(4s) + Image(2s) = 29s

Optimized Cold Path:
  Download(6s) + Frames(1.5s) + Audio(3s) + Analysis(4s) + Script(4s) + Image(2s) = 20.5s

Improvement: 29s → 20.5s = 29% faster
```

#### Download Method Selection Logic
```python
def select_download_method(url, attempt_count):
    if attempt_count == 1:
        return 'direct-cdn'  # Always try fastest first
    elif attempt_count == 2 and has_instagrapi():
        return 'instagrapi'  # Fallback to reliable
    elif attempt_count == 3 and has_rapidapi():
        return 'rapidapi'    # Try professional API
    else:
        return 'yt-dlp'      # Last resort
```
